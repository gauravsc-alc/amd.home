# GitHub Pages hosting guide

The active website is generated by Django and published as static HTML. The public domain is **www.amd.homes**; the repository name remains **amd.home**.

## Existing deployment model

1. Edit source under `content/`, `templates/`, and `static/`.
2. Build locally with the existing VS Code build task or `.\.venv\Scripts\python.exe build.py`.
3. Preview `/docs/index.html` through a local HTTP server and review changes.
4. Commit/push the approved source changes to `main` when ready.
5. [deploy.yml](../.github/workflows/deploy.yml) installs dependencies, generates placeholders, runs the build, and publishes `docs/` contents to `gh-pages`.
6. GitHub Pages serves the root of `gh-pages`, including the action-generated `CNAME`.

Use these repository **Settings > Pages** values:

```text
Source: Deploy from a branch
Branch: gh-pages
Folder: / (root)
Custom domain: www.amd.homes
```

Generated `docs/` files are ignored on `main`; this is intentional. Do not select `main /docs` or force-add output to make this workflow work. The previous guide's alternative `main /docs` instructions are not compatible with the repository's current ignore rules and automated publishing setup.

## Keep the domain stable across pushes

The publishing action has a checked-in `cname: www.amd.homes`. It no longer reads the `CUSTOM_DOMAIN` repository variable. [config.json](../content/config.json) sets `site_url` to `https://www.amd.homes` for canonical/social URLs and the sitemap. Editing metadata alone does not configure DNS or redirect browsers.

Follow the [domain correction guide](./DOMAIN_CORRECTION_GUIDE.md) for exact DNS values, GitHub settings, diagnosis of an unexpected redirect, and post-deployment checks. It distinguishes `amd.home` (repository) from `amd.homes` (domain) and `amd.com` (not the requested domain).

No registrar or GitHub account settings are changed by a local build. Verify domain ownership, configure DNS, and enable HTTPS using GitHub's official instructions linked in that guide. Do not remove unrelated DNS or email records.

## Static paths and animations

The build exports enabled pages and copies repository-owned assets to `docs/static/`. Relative page and static links support both a custom-domain root and a GitHub project subpath. No Django server, external image drive, or animation plugin is needed on GitHub Pages.

The concept controller starts when the illustration is visible, pauses offscreen, and respects reduced-motion preferences. Direct visibility checks on initial layout, scroll, resize, and load back up IntersectionObserver. See the [animation guide](./NAVIGATION_AND_ANIMATION_GUIDE.md).

## Before and after publishing

- Before: build, inspect the diff, test mobile/desktop navigation, galleries, animation controls, motion-off behavior, and asset loading.
- After: verify the latest Actions run succeeds, `gh-pages/CNAME` contains `www.amd.homes`, the live URL stays on that host, and canonical/sitemap URLs match it.
- If stale: confirm the deployed commit, hard-refresh or use a private window, and inspect live CSS/JS requests. Do not delete the domain or change DNS to troubleshoot a browser cache.
- If publishing fails: inspect the failed workflow log; do not assume the previous live deployment has been replaced.

Use [the image guide](./IMAGE_UPDATE_AND_DEPLOYMENT_GUIDE.md) for repeat imports and [the domain correction guide](./DOMAIN_CORRECTION_GUIDE.md) for domain recovery. Publish only after owner approval.
